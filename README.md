# 油品配送调度台

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia、Element Plus
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 测试：`npm test`（领域/并发/恢复集成测试 + jsdom 挂载冒烟）

数据默认保存在浏览器 localStorage 中。

## 调度模型

排车是车辆与罐容占用的载体，具有独立生命周期：

```
草稿(draft，冲突未解决，不占资源)
  └─重试通过→ 已预占(reserved) ──装车确认──▶ 已占用(occupied，在途)
                                            ├─ 到站确认 → 已完成(completed)
                                            └─ 在途失败 → 已释放(released)
               撤单 / 主动释放 ─────────────▶ 已释放(released)
```

- **派车前预占**：按配送单的计划到达时段（上午/下午/夜间，夜间跨零点）预占指定油罐车与吨数。
- **冲突保留草稿**：车辆检修、油品不适配/混装、超罐容、同时段撞车、该单已有生效排车等情况不会抢占任何资源，排车以草稿保留并逐条写明冲突，调整后重试，冲突解决才真正预占。
- **装车确认占用**：预占转正式占用，配送单进入运输中，车辆置为在途。
- **撤单 / 在途失败释放**：排车置为已释放、车辆恢复可用（同车还有其它在途排车时不回置）。
- **到站确认**：占用释放、排车闭环。

## 并发与可恢复性

- 每次状态变更都是一条**幂等操作**，经 `Web Locks` 跨窗口互斥：锁内重读最新台账 → 校验冲突 → 写操作日志 → 单键原子发布台账 → 清日志。两个窗口同时派同一辆车时，后提交者看到的是前者的最新占用，不会盖写。
- 写日志之后、发布台账之前的任意时刻关闭页面，重开时 `bootstrap` 自动回放未决日志接着完成，页面顶部会提示恢复条数。
- 列表、汇总、车队占用台通过 `storage` 事件随其它窗口的最新提交实时刷新。

## 旧台账迁移

- 旧数据键 `hxwlfront-19-oil-delivery` 原样保留留底；新台账写入 `…-ledger-v2`。
- 迁移闸门 + 迁移操作幂等保证**只迁移一次**：旧单 id、状态、备注不变，原始整条记录挂在 `legacy` 字段，列表中标记"旧台账迁移单"；同时补入标准车队。
- 旧版"运输中"但没有排车记录的单据可直接确认到站，不阻断旧流程。

## 目录

- `src/types.ts`：领域类型与状态枚举
- `src/domain.ts`：时段计算、冲突校验、操作纯函数（所有变更幂等可回放）
- `src/storage.ts`：原子台账、操作日志、崩溃恢复、一次性迁移、Web Locks 提交
- `src/seed.ts`：内置车队与示例现场（预占/占用/到站/冲突草稿）
- `src/store.ts`：Pinia 调度台 store、页面提示、跨窗口同步
- `src/components/DispatchEditor.vue`：单张配送单的派车面板
- `src/components/FleetPanel.vue`：车队罐容实时占用台
