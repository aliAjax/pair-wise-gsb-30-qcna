# 油品配送调度台

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia、Element Plus
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 逻辑自测：`npm run test:logic`（WAL 恢复、一次性迁移、冲突聚合、并发保护、释放与草稿恢复，共 13 项）

## 业务流程

每张配送单不再各自覆盖整表，统一进入可恢复的调度台账：

1. **创建配送单** → `待派车`（表单未提交也存草稿，刷新后可接着填）
2. **派车预占** → 按计划到达日期 + 上/下午时段，预占油罐车与罐容，单据转 `已预占`
3. **装车确认** → 占用明细由「预占」转「占用」，单据转 `装车中`
4. **发车** → `运输中`，在途期间罐容继续锁定
5. 终局：
   - **到站签收** → `已到站`，占用释放
   - **在途失败** → `在途失败`，占用立即释放，可按原单信息重新建单派车
   - **撤单**（发车前）→ `撤单`，预占 / 占用同步释放

## 冲突处理

派车提交前做事务内校验，冲突时**不产生台账版本、不写半份记录**，草稿（车辆、吨数、时段、冲突说明）落盘保留，页面逐条说清：

- `OVERLOAD`：同一计划到达时段内「预占 + 占用 + 本次」聚合后超过罐容（超量 / 撞车）
- `OVER_LIMIT`：本次吨数超过单车罐容
- `FUEL_MISMATCH`：该车不允许承运该油品
- `FUEL_MIX`：同一时段该车已安排其它油品，不能混装

改车、改时段后可直接再次提交。

## 可恢复写入（WAL）与多窗口一致性

数据保存在浏览器 localStorage：

| 键 | 内容 |
| --- | --- |
| `hxwlfront-19-dispatch-ledger-v1` | 调度台账主版本（车辆、配送单、占用明细、迁移标志、单调递增 `seq`） |
| `hxwlfront-19-dispatch-pending-v1` | 写写前记录（WAL）：先写它、再写主台账、最后清除 |
| `hxwlfront-19-dispatch-drafts-v1` | 派车草稿（按配送单保存，冲突 / 中断都不丢） |
| `hxwlfront-19-dispatch-create-draft-v1` | 建单表单草稿 |
| `hxwlfront-19-oil-delivery` | 旧版配送单表（迁移只读，永不删除 / 覆盖） |

- 提交后、主台账落盘前关闭或崩溃：重开时自动按 WAL 补全，并在页面顶部提示恢复结果。
- 每次提交带乐观锁序号：两个窗口同时派车时，后到者读到旧序号会被拒绝并自动重读最新占用重试，先来的占用不会被盖掉。
- 其它窗口写入后，本窗口通过 `storage` 事件刷新：车辆看板、汇总指标、剩余罐容、冲突提示全部跟随最新占用。

## 旧数据迁移

- 首次建账时读取旧台账，逐单迁入新结构：原记录、备注写进单据事件流；`待发车 → 待派车`、`运输中 / 已到站` 原状态保留，映射过程也写入事件流。
- 迁移成功后置 `meta.legacyMigrated`，与台账同一次 WAL 提交落盘，**只迁一次**；旧键原样保留。
- 旧数据无法解析时不覆盖、不删除，以空台账启动并告警，提示人工核对。
- 历史在途单迁过来时没有对应占用明细（旧系统无车辆数据），页面明确标注「旧台账迁入」，需要时重新派车即可。
